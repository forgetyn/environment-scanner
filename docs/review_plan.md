# 执行计划：environment-scanner 对抗式功能审查（v4.1.0）

审查标尺是这个 skill 的目标，不是代码风格：

面向非技术用户，只读扫描近期文档、已安装应用和知识库，由会话 AI 判断「哪几件事适合交给 AI、第一件怎么开始、该给 AI 什么信息」。判断必须通过本地确定性校验后，才渲染最终报告。

已公开、本轮不单独当成「没写进文档」的缺口：GBK 不探测、PDF/xlsx 只留文件名、Windows 入口与注册表未实机跑过。如果这些缺口会让判断把残缺证据当成完整事实，或者文档把没验证的能力说成已支持，仍然算问题。

## 阶段

1. 四路只读审查，各写各的报告，互不参照。审查 Agent 不改业务代码。
2. 一个汇总 Agent 只读四份报告和对应代码，逐条判断问题是否成立，丢掉站不住的，留下会让目标失败的。
3. 只对成立的问题写修复计划并改代码。不借机重做架构。
4. 另一个 Agent 审查这次改动：有没有改偏、有没有漏测、有没有引入新的目标偏离。
5. 按实际改动补测试，跑 `tests/test-skill.sh`、`tests/test-skill-behavior.sh`、`tests/test-skill-full.sh`。
6. 同步 `CHANGELOG.md`。行为有变化时再改 `SKILL.md` / `AGENTS.md`。

## 本轮要改（核实后）

只改核实报告里建议改的 6 条。C4、C6、C7、C10、C11、C12 不改。

1. 自述深读：关键词要成词（文件名等于关键词，或以关键词结尾），「如何 / 模板 / 关于我们」这类标题不读。全部知识库加起来最多 3 份。
2. 日记名额：日期必须在文件名开头才算日记。`1.1 背景` 这种章节号、`周报2026-10-01` 这种夹在名字中间的日期留在工作池。
3. `.pages` `.key` `.numbers` `.doc` `.rtf` 只留文件名，不读正文。`wallet` / `crypto` / `seed` 按整段或空格、下划线分出的词匹配，不再当子串。
4. 多个 OneDrive 时跳过空目录。扫描根不存在时记 `missing_root:`，不因此失败。
5. 私钥补常见 PEM、PGP、PuTTY。口令补引号、下划线前缀和中文「密码 / 口令」。比较前去掉 NUL。
6. 渲染报告时，已深读文件的摘录从报告副本里拿掉。证据 JSON 仍留给判断 AI。
