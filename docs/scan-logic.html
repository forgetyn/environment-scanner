扫描是怎么做的

脚本只负责收证据。会话里的 AI 根据证据判断哪几件事适合交给 AI、第一件怎么开始。本地脚本校验通过之后，才渲染最终报告。

版本 4.3.0 只读，不改用户文件 默认深度 deep 全程不出站
给谁用 面向不知道「自己哪些事能用 AI 提效」的普通人。扫描看的是近期文档、已安装应用的名字、以及本机 Obsidian / Logseq 知识库。目标是看懂这个人在做什么，再决定 AI 能接哪一段。

两步流程

入口有两个。第 1 步把电脑上的证据收成一份 JSON，并顺手渲染一页「证据报告」。第 2 步读会话 AI 写下的判断文件，校验失败就停，通过才写出最终 HTML 并打开。

证据报告是判断前的中间页，窗口不会自己弹出来。最终报告写好后才会用系统程序打开：macOS 用 open，Windows 用 os.startfile，Linux 兜底用 xdg-open。打开失败只提示路径，已经写好的文件仍然算成功。

第 1 步怎么启动

bash scripts/run-scan.sh [quick|standard|deep]

不写模式时读 config.json 的 default_config.scan_depth，现在是 deep。认不出的模式退回 deep。Windows 证据入口是 scripts/run-scan.ps1，最终报告入口是 generate-final-report.ps1。两步都还没有在真实 Windows 机器上跑过。解释器怎么选，见下一节。

产物放哪

默认目录 ~/.environment-scanner/reports，可用 ENV_SCANNER_OUTPUT_DIR 改。

文件名带秒级时间戳：environment-scanner-data / samples / apps / kb / evidence 的 JSON，外加 evidence-report 的 HTML。任一必备产物是空文件，整次扫描失败。

解释器从哪来

扫描逻辑仍是原来的 Python 标准库脚本。用户不用安装 Python，不用改 PATH，也不用管理员权限。Mac 的 bash 入口和 Windows 的 PowerShell 入口用同一顺序，只把选中的解释器绝对路径交给后面的脚本。

前一步能用就停。电脑上已经有合格的系统 Python 时，不会解压自带的那一份。

  1. 如果设置了 ENV_SCANNER_PYTHON，就只用它。它必须是一个能执行的文件，并且 import sys 后版本不低于 3.9。设了但不能用，扫描停下来，不再往下找。
  2. 如果 ~/.environment-scanner/runtime/<平台>-<架构>/ 里已经解压过，版本标记和工具清单一致，而且解释器能运行，就用它。
  3. 沿 PATH 先找 python3，再找 python。同样要能执行 import sys，版本不低于 3.9。路径里含 WindowsApps 的微软商店替身直接丢掉，不会不带参数去启动它。
  4. 否则核对压缩包的 SHA256，解压到上面的私有目录，再使用。校验不对就停，不使用坏包。
  5. 这个架构没有对应压缩包时，用白话说明并停止。不会打开微软商店，也不会安装 Xcode 命令行工具。

自带的是 CPython 3.12.14，来自 python-build-standalone 的 20260825 install_only 包。四份都在 runtime/vendor/：mac-arm64、mac-x86_64、windows-amd64、windows-arm64。python.org 的 3.12.14 目录只有源码包，没有 Windows embeddable zip，所以 Windows 用的是同一类解压即用的构建。扫描过程不下载这些文件。

解压后如果根目录出现 python*._pth，会改写成包含对应的标准库 zip、当前目录和 import site，这样脚本目录里的 common.py 仍能被导入。现在这四份包里没有该文件。

Gatekeeper 技能文件夹若是从网络下载的，macOS 可能拦住未签名的解释器。脚本不会清除隔离标记，也不会关闭这项保护。本机复制或 git 检出通常可以直接运行。

五个采集阶段

顺序固定。前一阶段的 JSON 是后一阶段的输入。知识库阶段可以关掉，关掉之后证据里的知识库和深读就是空的。

阶段 2 可以额外带上显式文档：环境变量 ENV_SCANNER_INSIGHT_DOCS 用分号拆开，再加上命令行从第 2 个参数起的路径。冒号会切开 Windows 盘符，所以这里用分号。

阶段读什么写出失败时
1 计数
collect-data.sh → scan_collect.py		 四个扫描根里、跳过名单之外的全部文件。计数不按 quick / standard / deep 截断。 environment-scanner-data-*.json：文件数、体积、扩展名、目录聚合、磁盘、系统信息、scan_warnings。 根目录存在但打不开：抛出 RootUnreadable，不写输出，扫描停止。根目录不存在：记 missing_root:，继续。子目录打不开：跳过并记 unreadable:。
2 采样
sample_content.py		 同一批根，再加主目录有限发现。只把文档扩展名送进候选。 environment-scanner-samples-*.json：files、rejected_documents、天数、警告。 扫描根不可读同样整次停止。单个文件读不出：记 unreadable:，换下一份。正文里有私钥或口令：整份丢进拒绝名单。
3 应用
app_inventory.py		 只读应用名字。macOS 是 /Applications 与 ~/Applications 的一级 .app。Windows 是卸载表 DisplayName，再加上 Program Files 的一级目录名。 environment-scanner-apps-*.json。名字按大小写不敏感去重、排序，超过 400 个截断并记 app_list_truncated。 没有 winreg 时记 windows_registry_unavailable，仍继续收 Program Files 目录名。应用内容一律不读。
4 知识库
kb_discover.py		 从主目录找 Obsidian / Logseq。库内统计笔记、日记习惯，并深读自述。 environment-scanner-kb-*.json。 ENV_SCANNER_KB_DISCOVER=0 时跳过这一阶段，不产生 kb 文件。目录预算或 20 秒到了记 kb_budget_reached。
5 合并
evidence_pack.py + judgment.py render		 把上面几份 JSON 合成一份，并算出热度、周分布、AI 痕迹。 证据 JSON + 证据报告 HTML。判断参数为空，所以报告里的建议区写着「等待 AI 判断」。 data / samples / apps / evidence / 证据报告有一个是空文件就失败。知识库关闭时不要求 kb 文件存在。

扫哪些目录

有两条查找，范围不一样。四个扫描根负责计数和采样的主体。主目录发现只为采样多找一层近期文档，并且故意不走进已经扫过的四个根。

四个根都可以用环境变量换掉：ENV_SCANNER_DOCUMENTS、ENV_SCANNER_DESKTOP、ENV_SCANNER_DOWNLOADS、ENV_SCANNER_BOOKS。换根只看路径，不上传、不改文件。

计数字段容易看错的地方

字段实际含义
files.obsidian_notes文档根下面后缀是 .md 的文件个数。这是历史字段名，等于「文档根里的 Markdown」，不等于知识库笔记数。知识库自己的篇数在 knowledge_bases[].notes，那种统计包含 .md 和 .markdown。
files.recent_notes_7d上面那些 .md 里，修改时间落在 7 天内的个数。
files.ebooks书籍根里、跳过名单之外的全部文件，不限扩展名。
files.desktop_files桌面上的文件，再加下一层子目录里的文件。更深的桌面文件不进这个数。
files.desktop_dirs桌面第一层里、没有被跳过的目录个数。
storage 与 structure用桌面的完整遍历（不限两层），加上文档、下载、书籍。体积按根汇总。结构里的 top_dirs 用父目录名，至少 3 个文件，最多 12 个；extensions 最多 10 个。
count_is_total一直是 true。三种模式都不把计数截成 50 / 100 / 200。跳过名单排除的文件本来就不在计数里。计数的意思是「用来判断这个人在做什么的文件」。
图片和代码会进计数 只要不在跳过名单上，.png、.py 这类文件会计入个数、体积和扩展名分布。采样阶段另有一份文档扩展名白名单，这些文件不会被读正文。

Windows 的目录会先看 OneDrive

文档和桌面各自探测。把主目录下名字匹配 OneDrive* 的目录按名字排序，用第一个里面有内容的 Documents 或 Desktop。空目录跳过，避免字典序靠前的空 OneDrive 盖住真正有文件的那个。两个都没有时回到 ~/Documents、~/Desktop。下载始终是 ~/Downloads，不跟着重定向。书籍是「最终采用的桌面」下面的 书籍。

主目录发现在 Windows 上会跳过 AppData，以及会被 pathlib 穿过去的 junction 名，例如 Application Data、Cookies、Recent、SendTo、Start Menu、Templates、My Documents 这一类。这份说明不把集合里的占位字符串当成真实产品名。

macOS 主目录发现会跳过

LibraryApplicationsMovies MusicPicturesPublic .TrashCachesContainers Group Containers node_modulesvenv.venv distbuildtargetvendor

这些名字只在「主目录发现」和「从主目录出发的知识库发现」里生效。四个扫描根内部不套这张名单。文档根里如果真有一个叫 Library 的文件夹，计数和四个根上的采样仍会走进去，除非它同时命中下面的跳过规则。

三层跳过

原则：看不懂「这个人在做什么」的东西不进证据。软件自己的目录、运行日志、安装包和压缩包属于这一类。用户自己写的 pdf、docx、md，包括下载目录里的这些文档，仍然保留。

符号链接在每一层之前就丢掉，不跟随。配置里的 features.smart_filtering 一旦写了某一份名单（非空），就整份替换代码里的默认名单，不是合并。skip_system_files、skip_app_data、skip_cache_logs、skip_sensitive_dirs 这几个键当前脚本不读。

目录名整段相等才跳过

比较时忽略大小写。QQ 会跳过，QQ笔记 会看。关于QQ.md 是文件，不受目录名单影响。名单故意很短，Slack、项目文件夹这类说不清的名字不跳。

.ssh.gnupg.aws.kubeKeychains .gitnode_modules__pycache__venv.venv distbuildtargetvendor QQTencent FilesWeChatWeChat Files xwechat_files微信DingTalkWXWork loglogscrashcrashes CrashReporterCrashpad cacheCachestmptemp__MACOSX

另外两条不在名单里、由代码固定执行：名字以 . 开头的目录；名字以 .app 结尾的应用包（大小写不敏感）。所以 QQ 的应用包和 QQ 的数据目录都不会被翻进去，用户自己的「QQ笔记」目录会。

整词，而不是子串

wallet、crypto、seed 只在两种情况下跳过：去掉扩展名之后整段相等，或者被空格、下划线切开之后有一段相等。连字符不切开。

名字结果
seed-round.docx留下。连字符把整段连成一个词，不等于 seed。
Keyboard.md留下。不按子串去切 key。
my_seed.txt、seed phrase.txt跳过。下划线和空格会切开。

打开前就丢掉的文件

精确文件名（忽略大小写）：

.envcredentials.json id_rsaid_ed25519id_ecdsaid_dsa

后缀：

.pem.p12.kdbx.ppk .pfx.cer.crt.p8.keystore .dmg.pkg.exe.msi.msix .apk.deb.rpm.appimage .zip.rar.7z.tar.gz .tgz.bz2.xz.iso.cab .log
.key 是 Keynote 它在文档白名单里，采样时只留文件名，body_skipped 写成 keynote。不会把它当成私钥后缀。

有一个 pathlib 的边角：文件名恰好是 .pem（没有主名）时，后缀被看成空，第 2 层不会因后缀丢掉它，计数可能看见它。它也不在文档白名单里，采样不会打开它。

采样与名额

采样回答的是「最近在写什么」。它先在四个根里走一遍（规则与计数相同），再做主目录发现，然后按池子分配最多 120 个自动名额。正文阅读顺序跟最终名单一致，所以工作文件的摘录排在日记和下载前面。

一个文件先被分到哪个池

120 个名额怎么分

三个池都有文件时，先给日记、下载、书籍预留 8+12+4=24，工作第一轮最多 96，并且每目录 8。某个池是空的，就不预留它的上限，工作能拿更多。预留没用完的部分，最后也只回到工作池。

轮转时，目录按「该目录里最新文件」从新到旧排序。同一目录里，能读正文的排在只留文件名的前面，再比修改时间。显式路径若和自动候选重复，只留显式那一份。

正文预算跟着这份名单走 顺序是：显式路径 → 第一轮工作文件 → 日记 → 下载 → 书籍 → 工作回填。deep 最多读 80 份正文。排在前面的工作文件会先花掉每份 4000 字、合计 12 万字的预算。后面的文件可能只留下文件名，body_skipped 为 not_read。

什么样的文件进候选

扩展名必须在这份白名单里，并且（显式路径除外）修改时间落在模式窗口内：

.md.markdown.txt.csv .docx.pptx .pdf.xlsx.doc.rtf .pages.key.numbers
扩展名正文
.md .markdown .txt读前 200 行。标题取第一个 Markdown 标题（最多 120 字）。摘录丢掉空行、标题行、整行表格、整行粗体、分隔线。
.csv只留第一行。
.docx读压缩包里的 word/document.xml，去掉标签。
.pptx读前 3 页幻灯片的 XML。
.pdf .xlsx .doc .rtf .pages .key .numbers只留文件名。body_skipped 分别是 pdf、xlsx、doc、rtf、pages、keynote、numbers。会话 AI 若要理解 pdf 或 xlsx，得自己去读原文件。
大于 2 MB只留文件名，原因 too_large。不占用「读了正文」的次数，但占候选名额。

文本按 UTF-8 打开，无法解码的字节丢掉。GBK 的记事本文件可能缺字，当前版本不做编码探测。被判定为私钥或口令的文件会从近期名单消失，进入 rejected_documents，并且这一次阅读次数已经花掉，不会改读下一份来补。

日记怎么认定

日记只来自这个人自己的知识库配置。文件名像不像日期，不参与判断。没有知识库，或者插件开了但没写目录，就不统计日记习惯。那些日期开头的笔记留在工作池里，按工作文件的每目录上限和回填处理。

采样用的日记目录和统计用的是同一套规则。四个根上搜索深度是知识库的 max_depth 5；主目录发现开着时，主目录再搜 home_depth 4。命中库之后不再往库里面嵌套找另一个库。点开头的目录在检查标记之前就跳过，所以 ~/.logseq 这种应用自己的全局配置不会被当成图。

格式字符串存下来，不筛文件 Obsidian 的 format、Logseq 的 :journal/page-title-format 会写进证据的 format 字段。目录里叫 记事-1.md、周一记事.md 的笔记，只要在配置目录下，都算这个习惯的一篇。

知识库与自述深读

怎么找到库

  • 从主目录出发，深度配置是 5。目录预算 6000，或 20 秒。
  • 最多保留 3 个库。点开头的目录、平台跳过目录、构建目录先跳过，再看标记。
  • Obsidian：存在目录 .obsidian。
  • Logseq：存在文件 logseq/config.edn。
  • 找到之后不进这个库再找嵌套库。

库内统计

  • notes：库内 .md / .markdown 篇数。
  • recent_notes_7d：其中 7 天内改过的篇数。
  • top_dirs：父目录的名字（不是从库根数出来的路径），至少 3 篇，最多 8 个。笔记直接放在库根时，父目录名等于库名，不进入这张表。
  • journals：上一节的前 3 个习惯。

自述文档

用来回答「这个人是谁」。只看文件名主干，后缀限于 .md .markdown .txt。主干必须等于关键词，或者以关键词结尾。

个人总结个人画像自我介绍 关于我个人情况简历

主干里只要出现下面任一片段，整份不要：

关于我们如何怎么怎样 教程模板范文示例

所以 关于我.md、2024-个人总结.md 可以深读；关于我们.md、如何写简历.md、简历模板.md 不会。

全部库合在一起最多打开 3 份 先把各库命中的文件按修改时间从新到旧排好，只打开前 3 份，每份最多 500 行。某一份因私钥或口令被拒绝后，不会把第 4 份补上来。证据里仍保留被拒绝的路径和原因（rejected_deep_reads）。深读记录上的 vault 字段是文件父目录的名字。

Org 笔记不在日记统计里，也不是自述深读的后缀。

私钥与口令

文件名那一层已经挡住常见密钥文件。这里是打开正文之后的第二道：笔记里贴出来的密钥和口令，整份不能进入可引用证据。比较前会先去掉 NUL，避免 UTF-16 被误读成中间插了空字节的 ASCII。

认出什么原因标记
BEGIN … PRIVATE KEY，中间可以有 EC、ENCRYPTED、PGP 这类词，也允许多个空格private_key
出现 PuTTY-User-Key-Fileprivate_key
password、passwd、api_key、secret 后面跟着冒号或等号。允许引号，允许 DB_PASSWORD 这种前缀credential_assignment
中文「密码」或「口令」后面跟着 : = 或 ：credential_assignment

采样拒绝的文件只出现在 rejected_documents，判断校验不允许引用它们。深读拒绝的文件只出现在 rejected_deep_reads。两种拒绝都不把正文放进报告。

证据里有什么，图表数字从哪来

evidence_pack.py 把四份产物合成一份，版本号写 4.3.0。判断 AI 读的就是这一份。图表不在判断文件里。

字段来源
scan时间、模式、平台、系统、磁盘占用。磁盘用 shutil.disk_usage。
counts / storage / structure阶段 1。见「扫哪些目录」。
recent_files采样留下的文件：文件名、父目录、时间、扩展名、标题、摘录、body_skipped。
rejected_documents采样时因私钥或口令丢掉的路径。
apps / app_count / app_sources应用名单。AI 应用是名字里含关键词的子集，关键词见下。
activity_heat按近期文件的父目录名聚合，最多 10 个，带 last_active_days。
weekly_counts近期文件按修改时间放进 26 个周桶。没有文件的周不出现。
sample_extensions近期文件扩展名，最多 8 个。这和全量 structure.extensions 不是同一份。
ai_usage_signals在标题和摘录里数标记；再从应用名里挑 AI 应用。marker_files 是至少命中一次的文件数，file_ratio 是它除以近期文件数。
knowledge_bases / deep_reads / rejected_deep_reads阶段 4。关掉发现时为空。
scan_warnings四份产物的警告去重后接在一起。
zero_signal近期文件为空，并且应用名单也为空。为真时不允许写任何建议。

AI 痕迹标记

正文标记（用来扫标题和摘录）：\bAI\b、人工智能、GPT / Claude / Kimi / Gemini / DeepSeek / Copilot / Opus / FunASR、智能体或 agent、提示词或 prompt、skill、自动化、以及「引擎」后面跟冒号。应用名关键词：chatgpt、claude、cursor、codex、zcode、trae、grok、deepseek、doubao、kimi、gemini、copilot。这些词当前版本不调整。

四张图的数字

渲染器从证据算出 chart_payload，写进报告页面。判断 JSON 里没有图表字段，模型填了也不会被拿去画图。用户打开报告时，Chart.js 从 CDN 加载库文件，不上传扫描数据。离线打开时图表区降级成提示。这份说明页自身不加载任何外部脚本。

图数据

报告里的正文会再藏一次

证据 JSON 保留深读全文和近期摘录，给判断 AI 用。写进 HTML 的那份副本会改两处：深读的 text 换成「只给判断 AI、报告不展示」；若某条近期文件的路径和深读是同一个文件，摘录换成「与深读为同一文件，正文不在报告中展示」，标题清空。证据区展示深读时只留文件名、时间和行数。

知识库卡片上的日记行是：目录名、每日/每周/每月/每季、篇数、持续天数。每个库的卡片都会带上全部深读文件名。

判断合同与拒绝门

会话 AI 按 SKILL.md 写判断。脚本不评价句子好不好，只做能确定的检查。有一条不通过，最终报告不会生成。

判断大致分四步

  1. 画像。 看 ai_usage_signals。痕迹密就写 power，几乎没有就写 novice。新手档教从零开始；重度档讲怎么把零散用法收成可重复的流程。
  2. 诊断。 从近期文件、知识库、深读里归纳在做的事，最多 8 件。每件有活动名、ai_usage（none / occasional / deep）和一句时间占用。summary 回答最大的剩余机会在哪。
  3. 四张理解卡。 主要活动、关注领域、工作或学习方式、文件结构。每张 2 到 6 条，重要的可以挂引用。
  4. 建议三件套。 这件事里 AI 做哪一段、第一步怎么开口（引用了文件就必须写出文件名）、预期省掉什么。再加上 kind、是否快见效、工作量、理由、来源。
基础用法和升级用法 basic 只给还没用或偶尔用 AI 的事。upgrade 把已经在深度用的事收成可重复流程。证据里完全没有 AI 痕迹时，不允许出现升级型建议。画像是 power 并且写了建议时，至少要有一条升级型建议。

引用有两条通道

  • 文件：{"name": "活动方案.md"}。名字必须出现在 recent_files 或 deep_reads 的 name 里。只要 sources 里有文件名，first_step 的文字里就必须包含这些名字。
  • 指标：{"type":"metric","ref":"counts.ebooks"}。按点号在证据里逐级查找，找不到就拒绝。这样「电子书很多、还没动过」这类聚合判断可以被核对。
  • app_refs 里的每个名字必须在应用清单里。

校验会拒绝的情况

对象门
建议条数0 到 10。0 条时 insufficient_evidence 必须是 true；有建议时必须是 false。
零信号zero_signal 为真时，建议必须是空列表。
画像与诊断persona 只能是 novice 或 power。诊断要有非空 summary。活动最多 8 条，且 activity、ai_usage、time_note 都要有。有建议时活动不能为空。
每条建议要有不重复的 id。activity、ai_role、first_step、expected_saving、reason 非空。effort 是 low/medium/high。kind 是 basic 或 upgrade。quick_win 是布尔值。sources 至少一条有效引用。
理解与节奏有建议时，四张卡各 2–6 条；日/周/月各有 summary，以及 1–4 条事项。
优先级有建议就不能空着，最多 3 条。id 必须指向某条建议。why 非空。how_to_start 和 long_term 各 1–4 条。只要存在 quick_win，第一条优先级就必须是其中一条。
资产与结构资产最多 6 条，要有 title、what、why_valuable、1–4 条 how_to_use。结构建议最多 4 条，要有 title 和 detail。挂了 basis 的同样走引用检查。

最终报告的区块是：画像、整体理解、四张图、建议、日/周/月节奏、三段式优先级（为什么、怎么开始、长期帮助）、资产、结构建议，以及折叠的证据。对话里再用白话说出前三条。

三种深度

模式只改变采样窗口和正文预算。计数、跳过名单、知识库发现的深度都不跟着变。

有意不做的事

  • 不解开压缩包。zip 在后缀名单上，直接不看。
  • 不把普通 .txt 当成日志。只有后缀 .log，以及目录名是 log / logs 的，才跳过。
  • 不扫描 macOS 的资料库作为四个根的一部分。Library 只在主目录发现和知识库发现里跳过。
  • 不探测 GBK。txt / csv 按 UTF-8 忽略坏字节。
  • 不解析 pdf 和 xlsx 的正文。文件名会留下，需要时由会话 AI 自己读。
  • 不用文件名开头是不是日期来认日记。
  • Linux 没有采集入口。适配器只是兜底：应用名单为空，并记 app_inventory_unsupported_platform:linux。不要临时拼一套等价命令。
  • Windows 的 run-scan.ps1、find-python.ps1、generate-final-report.ps1、注册表和 os.startfile 还没有在真实 Windows 机器上执行。32 位 Windows 不支持。
  • 判断校验不检查句子是否具体、是否像套话。那部分靠会话 AI 遵守准则，脚本只核对引用和结构。
  • 不改名额（120 / 8 / 3 / 12 / 4），不改周频公式，不改 AI 关键词表。
安全边界 可以在输出目录写本工具自己的 JSON 和 HTML。不修改、不删除、不移动扫描根里的用户文件。不要求完全磁盘访问权限。除了用户后来自己打开报告时浏览器去取 Chart.js，扫描过程不访问网络。
